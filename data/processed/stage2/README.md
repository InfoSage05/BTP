# Stage 2 results: MLP fine-tuning per domain

Fine-tunes the Stage-1 pretrained MLP checkpoint on each small, real,
distinct-domain dataset in data/raw/fine_tuning/, versus an identical
from-scratch MLP trained on the exact same split -- this comparison is the
whole point: does pretraining on the synthetic LUT corpus actually transfer
to a different fluid/geometry, or not.

## Domains covered, and why some were skipped
- INCLUDED: hardik2016_coils_r123, hardik2017_straight_tubes_r123,
  kaeri_uniform_water, kaeri_nonuniform_water, zhao2020_tubes_water.
- SKIPPED: helical_coil_r123_appendixCD.csv -- no diameter column in this
  file, and no reliable source table available this session to reconstruct
  one (this is a different Mendeley dataset from hardik2016, not guaranteed
  to share the same coil geometries). Rather than fabricate diameters, it
  was left out.
- SKIPPED: pinfin_chf_water_fc72.csv -- this is pool-boiling data (only a
  subcooling column, no pressure/mass-flux/quality at all). It cannot be
  expressed in the (P,G,X,D) flow-boiling feature schema this model uses
  without a fundamentally different input space. Out of scope for this pass.

See scripts/chf_pipeline/finetune_mlp.py's module docstring for the exact
unit conversions and column mappings used per domain, including the
hardik2016 Coil_No -> diameter mapping (taken directly from that papers own
Table 4, cross-checked against the CSVs own per-coil row counts, which
matched exactly: 47/29/18/22/31/9).

## Results

| Domain | Fluid | n(test) | Pretrained+FT R2 | Scratch R2 | Pretrained+FT MAPE | Scratch MAPE |
|---|---|---|---|---|---|---|
| hardik2016_coils_r123 | R123 | 31 | 0.562 | **0.633** | 33.5% | 30.3% |
| hardik2017_straight_tubes_r123 | R123 | 11 | **0.481** | -0.171 | 14.4% | 16.7% |
| kaeri_uniform_water | water | 130 | 0.908 | **0.914** | 7.7% | 8.0% |
| kaeri_nonuniform_water | water | 177 | **0.867** | 0.770 | 16.8% | 11.5% |
| zhao2020_tubes_water | water | 287 | **0.891** | 0.873 | 10.5% | 11.5% |

## Honest reading
Mixed, not a clean win either way -- pretraining helps in 3/5 domains
(hardik2017, kaeri_nonuniform, zhao2020) and is roughly tied-or-slightly-
worse in 2/5 (hardik2016, kaeri_uniform). The clearest win is
hardik2017_straight_tubes_r123 (0.481 vs -0.171 -- from-scratch is
actively broken there, pretraining rescues it), but that test set is only
11 rows, so treat the exact numbers as directional, not precise. Same
caveat applies to hardik2016 (n=31 test) -- with samples this small,
several-point R2 swings can be noise rather than a real pretraining-hurts
signal.

The two R123 domains (both small, both hardik papers) show the weakest or
most ambiguous transfer -- unsurprising, since the pretraining corpus and
the water core dataset are entirely water-based; R123 is a genuinely
different fluid the model has not seen physical trends for beyond the
dimensionless P_reduced/density_ratio features carrying some transfer on
their own.

## Known limitations, stated plainly
- Per-domain test sets are small (11 to 287 rows) -- these R2 values have
  real sampling noise, not tight confidence intervals.
- kaeri_nonuniform treats each rows reported HeatFlux as a per-test summary
  CHF value, not a modeled axial profile -- a real simplification (see
  script docstring).
- Two real fine-tuning datasets (helical_coil_r123_appendixCD, pinfin) were
  skipped rather than forced into a schema that does not fit them.
- Fine-tuning used a fixed small learning rate (1e-4) and epoch budget
  (150, early-stopped) uniformly across all domains -- no per-domain
  hyperparameter search was run.
