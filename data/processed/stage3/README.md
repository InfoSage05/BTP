# Stage 3 results — deep ensemble (8-member MLP)

8 pretrained+fine-tuned MLPs per context (different weight-init/minibatch
seeds, same train/val/test split per context), averaged in log-space.
Run across all 7 evaluation contexts built so far: the two Stage 1 core
splits (interpolation, extrapolation @ 14 MPa cutoff) and all 5 Stage 2
fine-tuning domains.

## Two honest findings, not one clean win

**1. Ensembling barely beats a single model.** Across every context, the
ensemble R2 is within ~0.001-0.002 of the single-model mean. The
single-model std across seeds is tiny everywhere (0.001-0.03) -- the 8
members consistently converge to nearly the same solution. That's not
surprising for a small, well-regularized MLP fine-tuned from a shared
pretrained checkpoint; it does mean the *accuracy* benefit of this
particular ensemble recipe (vary seed only) is marginal.

**2. The uncertainty estimates are badly miscalibrated.** 95% interval
coverage ranges 9-22% across every single context -- it should be ~95%.
Because the members agree with each other (low std) but are all making
correlated errors against the true values, the ensemble's spread
massively understates real prediction error. **Do not trust this
ensemble's uncertainty bands as-is.** The accuracy numbers (R2, MAPE) are
real; the confidence intervals implied by ensemble spread are not.

## Why this happened, and the fix for next time
Same-seed-only ensembling (same data, same architecture, only weight init
differs) produces low-diversity members when starting from a shared
pretrained checkpoint -- they're all pulled toward the same basin. Two
standard fixes, not yet implemented:
- **Bootstrap the training data** per member (resample training rows with
  replacement), not just the weight init -- this is what actually
  diversifies predictions on held-out points.
- **Vary architecture width/depth** per member (a true "ensemble of
  different models," not same-model-different-seed).
