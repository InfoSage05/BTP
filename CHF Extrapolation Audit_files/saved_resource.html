01 Executive summary

The team has built a methodologically careful benchmark-and-audit study on the 2006 Groeneveld CHF look-up table — not yet the engineered-surface CHF study the advisor's own paper outline describes. Both facts are supported directly by files in this repository.

The single most important finding

Your team's own docs/manuscript/literature_survey_draft.txt (lines 9–10) already states this plainly: "The supplied outline is written for a new experimental database covering engineered surfaces... The current BTP repository is a different study; it uses the 2006 Groeneveld look-up table and contains only pressure P, mass flux G, thermodynamic quality X and CHF." The advisor's outline (docs/manuscript/paper_outline.docx) asks for surface roughness, wettability, contact angle, CHF-detection criteria, an experimental facility diagram, and leave-one-surface-out validation — none of which exist anywhere in this repository. This is not a hypothetical risk; it is an acknowledged, unresolved scope gap that needs an explicit conversation with Dr. Pattanayak before more manuscript time is spent.

Within the scope the team actually pursued, the work is genuinely strong: a three-tier validation protocol (random split / interior pressure holdout / edge-pressure extrapolation) correctly separates interpolation from extrapolation; ten-plus model families were benchmarked; a single-seed "best result" (pressure-gated blend, R²=0.855) was caught, multi-seed-verified, and publicly retracted inside the project's own documentation (docs/SENIOR_REVIEW.md); and two physics-informed approaches failed in mechanistically well-explained ways rather than being swept under the rug.

But three things currently block publication, independent of the scope question above: (1) the headline "PINN" number of R²=0.8123 was very likely selected using the extrapolation test set itself, contradicting the project's own stated rule; (2) the best-performing "physics-informed" residual model has its physics-penalty weights tuned to exactly zero, meaning the physics constraints are not doing any of the claimed work; and (3) the literature review's comparison table presents specific author names, DOIs and metrics for roughly fifteen papers that are explicitly caveated in the same file as unverified against full text. Each is addressed with file-level evidence below.

02 What this BTP is actually trying to solve

Professor-statedEvidenceInferenceSpeculative

Core problem evidence

Critical Heat Flux is the heat-flux threshold at which nucleate boiling on a heated surface transitions to a vapor-blanketed regime (departure from nucleate boiling / dryout), causing a sharp, potentially damaging rise in wall temperature (docs/CHF_Project_Simple_Explanation.md:9–16; docs/manuscript/literature_survey_journal_ready.md §1.1). The BTP's task is to predict CHF as a function of pressure (P), mass flux (G), and thermodynamic quality (X) using the 2006 Groeneveld look-up table (11,088 usable rows after removing 504 all-steam placeholder zeros), and to test whether that prediction survives being asked about pressures never seen in training.

Domain and stated application inference — internally inconsistent

The professor's emails (docs/Mail_ID_content.txt) frame the motivation entirely in reactor/nuclear thermal-hydraulics terms and ask for flow-boiling CHF datasets with inputs "length, diameter, mass flux, dryness fraction, pressure." The literature-survey manuscript frames the motivation the same way — PWR/BWR/SMR fuel-cladding safety margins (§1.1). But docs/project_status.pdf (p.1) is titled "Weekly Project Update: CHF Prediction for Lithium Battery Cooling" and frames the same work as battery thermal management. Nothing in the professor's emails mentions batteries. This is either an internal team reframing that was never sent to the advisor, or a stray document from a different context that drifted into the shared repo — either way, the project currently has two incompatible statements of "why this matters" living side by side, and only one of them can be the one the advisor actually endorsed.

Expected inputs / outputs evidence

Input: (P, G, X) triplet, each a scalar float. Output: CHF in kW/m². The advisor's outline (Part 7 below) implies a much larger input vector for the intended paper — geometry, fluid properties, and surface characteristics — that the current pipeline does not accept.

Constraints and assumptions evidence

  • Only water, only vertical tubes normalized to an 8 mm reference diameter (the LUT's own domain, per Groeneveld et al. 2007).
  • X=1.0 rows are placeholder zeros, not measurements, and are excluded (docs/CHF_ML_Context.md:38–41) — a correct and verified cleaning decision.
  • CHF spans 15–44,338 kW/m² (three orders of magnitude), forcing a log-target treatment for most smooth models.
  • The table itself is discrete and empirical; the manuscript draft is explicit that "interpolation should not be confused with a fundamental CHF law" (§1.2) — a correct, non-trivial epistemic caveat that a weaker paper would have glossed over.

Practical vs. scientific contribution intended

Inference: practical impact is "tell an engineer which ML model family is safe to trust outside its training envelope, and by how much it degrades." Scientific contribution intended, per the literature draft's own framing (§2.6): resolve four methodological gaps in how CHF-ML papers currently validate themselves (interpolation/extrapolation conflation, tree-ensemble extrapolation collapse, PINN-taxonomy confusion, single-seed reporting). Whether that framing survives contact with the closest prior art is assessed in Part 9 and Part 11.

04 Research question and hypothesis

Primary research question evidence, as stated in manuscript draft §1.5

How do diverse ML model families perform when systematically transitioned from optimistic random interpolation to structured interior holdout and honest edge-extrapolation regimes, and do physics-informed extensions measurably improve true out-of-domain extrapolation on the 2006 Groeneveld CHF table?literature_survey_journal_ready.md §1.5

Secondary questions evidence

  1. Do tree ensembles structurally fail at pressure extrapolation regardless of tuning? (Answered: yes, mechanistically explained — piecewise-constant leaf outputs.)
  2. Are single-seed neural-network extrapolation scores reliable? (Answered: no — directly demonstrated via retraction.)
  3. Do physics-guided features, residual learning, soft-penalty constraints, or gated blends improve extrapolation over a plain smooth model? (Answered, mostly: two failed outright; one (soft-penalty) helped only marginally and only when layered on a strong deterministic baseline, at which point its own physics terms went to zero weight — see Part 9.)

Hypothesis inference — implicit, never written as a single falsifiable statement

No single-sentence, falsifiable hypothesis appears anywhere in the repository. The closest equivalent is the four-level "research gap" framing (Part 11). For a journal submission this needs to be sharpened into an explicit claim of the form "physics-constrained residual learning on a deterministic table baseline improves edge-pressure extrapolation accuracy over both the baseline and an unconstrained neural network, without requiring the physics terms to be active at the optimum" — which is in fact closer to what the data show (Part 9) than the framing currently in the manuscript draft.

Expected contribution if the hypothesis holds inference

A validated, reproducible protocol for auditing CHF-ML extrapolation claims (splits + multi-seed verification), transferable to any future dataset the team collects — this is the most durable output regardless of how the novelty question resolves.

05 Research context and literature mapping

The manuscript draft's own Table 1 (literature_survey_journal_ready.md, §2.5) is a genuinely useful map, so this audit reuses its structure rather than re-deriving one. Four clusters matter for novelty positioning:

Cluster A — the table itself

Groeneveld et al. 2007 (the LUT), Hall & Mudawar 2000 (world CHF data compilation), Groeneveld 1986/1995 predecessor tables. Establishes the dataset as an international standard, not a novel data source the team collected.

Cluster B — closest prior art

Yang et al. (2026, Applied Thermal Engineering, ref [47]) pretrains a DNN on this exact same LUT, then fine-tunes on 1,637 tube + 768 5×5-bundle experimental points, and already performs "window-type extrapolation mapping" with reported R²≈0.985. This is the paper the team itself calls "the primary reference benchmark" — and it already does, with real experimental fine-tuning data, most of what this project does with LUT-only holdout.

Cluster C — the PIML taxonomy this project reinvents

Wu, Gui & Wu (2025, NED, ref [65]) already compares physics-guided features, residual/deviation learning, and soft-penalty PINN formulations for CHF — the exact three-way taxonomy behind this project's Phase-2 "Approaches 1–3." The novelty has to be "we did this specific comparison on the specific extrapolation axis these authors didn't test," not "we invented this comparison."

Cluster D — surface-characteristic CHF ML

Serrao et al. 2025 (ref [73], n=850, ATF surface roughness/wettability, leave-one-surface-out, SHAP) is the closest existing analogue to what the advisor's outline actually wants — and it already exists, at small N, meaning even the "engineered surface" pivot would need to clearly out-do or meaningfully extend this specific paper, not just resemble it.

Net position: the team is benchmarking on a dataset and along a taxonomy that two 2025–26 NED-track papers have already substantially covered. That does not make the work worthless — see Part 9 for what remains defensible — but it does mean the "four-level research gap" claim in the manuscript draft is currently overstated relative to what Clusters B and C already establish.

06 Reference-by-reference analysis

The manuscript draft's Table 1 already performs this exercise for 18 studies at the level of depth requested (dataset, geometry, inputs, model, physical constraint, validation strategy, metrics, strengths, gaps). Rather than duplicate all 18 rows, this section flags what a skeptical reviewer would check first, and records the single most important caveat the team's own draft already discloses about that table.

Provisional-citation flag integrity risk, not yet resolved

literature_survey_journal_ready.md §2.5 states, in the table's own caption: "Dataset sizes, architectures and reported metrics for refs. [58], [61]–[75] are drawn from title/topic matching pending full-text confirmation and should be treated as provisional." That is roughly fifteen of the eighteen comparison rows — each with specific author names, journal volumes, page numbers, DOIs, and numeric R²/MAPE values presented in normal table formatting indistinguishable from confirmed entries. This is exactly the failure mode research-integrity bodies (COPE) warn about: a caveat that is true and disclosed today, but invisible the moment someone copies this table into the actual submission draft without carrying the footnote. This is a "critical blocker," not a stylistic nitpick — every one of those ~15 rows needs the actual PDF pulled and the row corrected or removed before this table can appear in anything sent to a journal.

08 Complete audit of work done so far

Data evidence

  • Primary dataset: 2006 Groeneveld LUT, digitized to 11,592 grid rows (24P×21G×23X), cleaned to 11,088 rows by removing 504 X=1.0 placeholder zeros. Verified independently against the project's own stated facts by docs/SENIOR_REVIEW.md §1 ("no further cleaning is needed... verified end-to-end").
  • Secondary/mentor dataset: 55 real experimental rows (data/raw/mentor_master_experiments.xlsx) with 14 "green" columns; the team discovered and correctly excluded a target-identity leak (CHF = Pnet/(L·Width) exactly, max error 0.0) before modelling — a genuinely good data-leakage catch (PLAN_2.md:30–38).
  • Tertiary/external dataset: 468 rows parsed from a PDF appendix (55 R123-straight, 156 water-helical, 140+117 R123-helical at low/high pressure) — used only as a zero-shot diagnostic, never as training data. Results are catastrophically poor (R² from −390 to roughly −2×1015 across tables, per results/plan2/external_validation_report.csv) — correctly interpreted by the team as evidence of domain shift (different fluid, different geometry), not model failure, but this also means no unified cross-geometry or cross-fluid model exists yet in any form.
  • No original experimental data. A CAD experimental rig is mentioned as "underway" (project_status.pdf §11) but no CAD files, facility description, or measurements exist anywhere in the repository. Status: planned but not started.

What this table means in one sentence

Every individually strong result in this project is either confirmatory of what is already known/suspected, a direct reuse of an existing taxonomy from a paper the team has already read, or marginal once you look past the headline number. The one place genuine novelty survives scrutiny is the reproducibility-auditing angle — which the current manuscript draft does not yet foreground as the paper's main selling point.

10 Intended novelty / research contribution

Inferred from the manuscript draft's framing (§2.6–2.7): the team is aiming to be the paper that "simultaneously addresses structured-table leakage, target scaling, multi-seed stability, physical constraints and edge extrapolation" for CHF — i.e., a methodology and rigor paper positioned as filling gaps in how the field validates itself, rather than a paper claiming a new predictive method.

Current demonstrated novelty: a disciplined, multi-seed-audited benchmark of existing model families and an existing PIML taxonomy on a well-known table, with one genuine reproducibility case study (the retraction) and two well-diagnosed negative results.

Intended future novelty speculative, not yet demonstrated: if the advisor's engineered-surface direction is pursued, the novelty target shifts to cross-surface generalization with leave-one-surface-out validation and SHAP-based surface-feature interpretability — a materially more novel and more publishable direction, contingent entirely on acquiring a dataset that does not currently exist in this repository.

Required evidence to validate the current (narrower) novelty claim: (1) a corrected, non-leaked PINN/residual result; (2) an explicit statement that the physics terms are inert at the optimum, framed as a finding rather than hidden; (3) a statistical significance test between the top 2–3 Split-C models, since a 0.006 R² gap between the residual ensemble and plain grid interpolation is currently asserted, not tested, to be real.

12 Current methodology assessment

Sound in its bones: log-target handling, train-fold-only scaling, explicit multi-seed protocol, a caught and fixed Split-B sandwiching bug, and a documented refusal to use the Groeneveld correlation family itself as a physics prior (correctly identified as a leakage risk since the LUT was partly built from Groeneveld correlations — scripts/chf_physics.py:6–10). This is better data-leakage hygiene than the median published CHF-ML paper in the team's own comparison table shows.

Weak points: (1) the 720-config PINN grid search selected against Split C directly (Part 13); (2) no nested cross-validation or held-out validation band was used consistently across all four physics-informed approaches — only later Tier 1/2/2b iterations adopted a proxy band; (3) hyperparameters for the classical ML baselines (RF/XGB/LGBM depth, n_estimators, etc.) are not documented in any file reviewed, making those specific numbers hard to audit even though the split protocol around them is sound.

13 Experimental rigor assessment

Test-set tuning risk — the most technically important single finding in this audit

The project's own context document states the rule explicitly: "Never tune any hyperparameter using the Split C (extrapolation) test data — that would be leakage into the very test meant to be honest" (docs/CHF_ML_Context.md:137–140). Yet docs/GOOGLE_DOC_SUMMARY.txt §6.5 presents "PINN Grid Search Results — Top 15 Configurations (Split C, 5-Seed Mean)" as the basis for selecting the winning 128×128×64 architecture out of 720 candidates — i.e., the model that produced the oft-cited R²=0.8123 headline number appears to have been chosen by looking directly at Split C performance across hundreds of configurations. project_status.pdf §9 confirms the fix came later: "The main tuning lesson was that the model should not be selected using the real high-pressure test rows. The proxy search used lower pressures for training and the 15,000–16,000 kPa band for validation; only the final selected configuration was evaluated at 17,000–21,000 kPa" — but this correction applies to Tier 1/2/2b (R²=0.73–0.85), not to the original 0.8123 number, which is still the figure quoted in the literature-survey manuscript's positioning section and in GOOGLE_DOC_SUMMARY.md. A reviewer who checks this would flag it immediately; it needs to be re-run under the proxy-band protocol and the old number retired before any submission, exactly as the R²=0.855 gated-blend number already was.

Other rigor gaps

  • No significance testing anywhere: every model ranking (e.g., residual ensemble 0.847 vs. grid interpolation 0.8415) is reported as a point estimate; no bootstrap CI or paired test establishes whether a given gap exceeds seed/sampling noise.
  • No ablation isolating the physics terms' contribution in the winning Tier 2b model, despite the grid search itself showing lam_mono=lam_zuber=0 is optimal — the paper needs to say this plainly rather than let a reader infer it from a JSON file.
  • Small-N mentor data (n=55) grouped-CV result (R²=0.914) is explicitly self-flagged in PLAN_2.md as "not proof of final performance," which is the correct posture — but this also means it cannot yet support any publication-strength claim.
  • External-validation R² values are not physically interpretable (values like −2×1015) and, while correctly labeled "diagnostic_only," would need a bounded or rank-based metric (e.g., MdAPE, within-20%-band) reported instead of raw R² if shown in a paper, to avoid looking like a reporting error.

14 Reproducibility assessment

What reproduces well

  • Notebooks are executed with saved outputs, not just static code (verified programmatically: 12/12, 8/8, 13/14 code cells carry outputs across the three main notebooks).
  • results/seed_and_version_log.json pins the global seed (42), Split-A seed list (0–4), GPR subsample size, and exact library versions used at run time.
  • Rebuild scripts exist for every notebook (scripts/build_notebook*.py) and for the data pipeline (prepare_data.py), and the repo is under git version control with CI configured (.github/workflows/).

What would block a stranger from reproducing this

21 Strongest possible paper story

CHF prediction is safety-critical, and published ML studies routinely report near-perfect accuracy that reflects grid memorization, not generalization (Problem/Motivation). Existing work already flags this risk in principle ([48]) and closely related papers ([47],[65]) study parts of it, but neither reports a case where a single favorable random seed produced a headline result later shown, by the same authors, to be unrepresentative under 30-seed verification (Gap). This paper asks: how much does seed selection and validation-band discipline change the apparent ranking of CHF-ML and physics-informed methods under genuine pressure-edge extrapolation, and can a simple, leakage-clean residual-on-table-baseline model be made to beat a deterministic physical baseline reliably (Research question/Hypothesis)? Using the complete 2006 Groeneveld LUT, ten model families and four physics-informed extensions are benchmarked under a three-tier split protocol with mandatory multi-seed reporting (Method). One early result (R²=0.855) is shown, and then retracted, on camera (in the data), demonstrating the failure mode concretely; a corrected, leakage-clean residual ensemble reaches R²=0.847 against a deterministic R²=0.8415 baseline — a real but small gain whose own physics-penalty terms are shown, by the grid search itself, to contribute nothing at the optimum (Results). The paper's honest contribution is therefore a validated auditing protocol and a demonstrated case study of how much single-seed, test-leaked reporting can mislead — not a new state-of-the-art predictor (Analysis/Limitations). This is scientifically meaningful because it targets a documented, field-wide reporting weakness with a concrete, reproducible demonstration rather than another marginal accuracy claim (Implication).

This story (Direction B) is the version of the paper the current evidence base can support without exaggeration. The advisor's engineered-surface story (Direction A) would be more exciting but is not yet evidenced by anything in this repository.

26 Plain-language explainer

What are we trying to do? Predict the pressure/flow/steam-quality combination at which a water-cooled tube's surface would suddenly overheat (CHF), and find out whether machine-learning models that look accurate inside their training data are still accurate outside it.

Why does it matter? Because this exact failure — a model that looks perfect on paper but fails at conditions it never saw — is a real safety concern in reactor thermal design, and (per one internal document) possibly battery cooling design, though which of those two applications the advisor actually wants is currently unresolved.

What does existing research already know? That tree-based models are excellent inside their training range and bad outside it (general ML fact, now also shown here); that physics-informed tricks can help CHF models generalize (shown by others, replicated in part here); and that a very closely related paper already pretrains on this same table and fine-tunes on real experiments with better numbers than this project currently reports.

What gap are we targeting? Mainly: nobody has shown, concretely, how badly a single lucky random seed can mislead a CHF-ML paper's headline claim — this project shows it, on itself, and fixes it.

What have we built? A ten-model benchmark, four physics-informed variants, a multi-seed audit tool, a small real-experiment leakage audit, and a diagnostic external validation test — all on a 2007-published reference table, plus a start on the paper's introduction and literature review.

What have we experimentally demonstrated? Tree models collapse under pressure extrapolation (R²: 0.999→0.43); smooth models and table interpolation hold up much better (R²≈0.75–0.84); one impressive early result was a statistical fluke and has been publicly retracted; a residual neural correction on top of the table narrowly beats the table alone, but not because of the "physics" terms — those turned out to be worth zero in the best configuration.

What is genuinely novel right now? The retraction and the mechanistic failure diagnoses. Everything else mostly confirms what two very similar 2025–26 papers already show.

What novelty are we trying to achieve? Depends on an unanswered question: does the advisor want the bigger engineered-surface paper the outline describes, or is the current table-based work the actual paper? That decision has not yet been made explicit.

What remains to be done? Fix the one leaked test result, verify the borrowed citations, decide the scope question with the advisor, run a significance test, and then — only then — write the paper's back half.

What would the eventual paper claim? Most defensibly: "single-seed and test-leaked reporting can substantially mislead CHF-ML extrapolation claims; here is a validated protocol, and a modest but honestly-reported residual model, that avoids it."

28 Strict reviewer-style critique

If I were a reviewer, why might I reject this paper?

  1. The headline PINN result appears to have been selected using the test set it is supposed to be evaluated on — this alone is grounds for a major-revision or reject decision at a serious venue.
  2. The "physics-informed" framing is not supported by the paper's own best configuration, where the physics penalty weights are zero — this reads as a mislabeled contribution if not corrected.
  3. The core empirical findings (tree extrapolation collapse, PIML taxonomy comparison) closely track two papers already in the reference list ([47], [65]) without a sharp enough differentiation of what is actually new.
  4. No statistical test establishes that the reported "best model" differs meaningfully from the deterministic baseline it barely edges out.
  5. Several comparator studies in Table 1 are cited with specific metrics that the authors themselves flag as unverified — unacceptable in a submitted manuscript.
  6. The dataset is a single, decades-old, secondary (tabulated, not raw experimental) source; no independent experimental validation succeeded.

What would make me change my recommendation?

  • A re-run, leakage-clean PINN/residual result with the physics-term ablation stated explicitly as a finding rather than buried in a JSON file.
  • A significance test showing the residual ensemble's edge over grid interpolation is real.
  • A verified literature table with no provisional entries.
  • A sharply reframed novelty statement centered on the retraction/rigor story (Direction B) — or, if time and data allow, real progress on the engineered-surface direction the advisor actually asked for.
  • At least one genuinely independent validation result (even small-N, if honestly caveated) that isn't a diagnostic negative result.

Determine whether machine-learning and physics-informed models can predict Critical Heat Flux reliably when asked about pressure conditions beyond their training range, using the 2006 Groeneveld look-up table as the initial testbed for a paper the advisor intends to be about engineered-surface CHF prediction.
